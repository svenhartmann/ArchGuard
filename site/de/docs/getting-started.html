Erste Schritte

Installiere ArchGuard, öffne ein Projekt und verstehe deine erste Analyse.

Den neuesten Release installieren

Ein Befehl lädt den neuesten veröffentlichten Release für dein Betriebssystem und deinen Prozessor herunter, prüft ihn gegen die SHA256SUMS des Releases und installiert die ausführbare Datei. Eine Rust-Toolchain ist dafür nicht nötig.

macOS, Linux, Git Bash (Installation nach ~/.local/bin):

curl -fsSL https://raw.githubusercontent.com/@@REPOSITORY@@/main/scripts/install/install.sh | sh

Windows PowerShell (Installation nach %LOCALAPPDATA%\Programs\archguard; das Verzeichnis wird deinem Benutzer-PATH hinzugefügt):

irm https://raw.githubusercontent.com/@@REPOSITORY@@/main/scripts/install/install.ps1 | iex

Setze ARCHGUARD_VERSION, um eine Version festzulegen, beispielsweise 0.1.3, oder ARCHGUARD_INSTALL_DIR für ein anderes Zielverzeichnis. Du kannst das kurze Skript vor dem Weiterreichen an eine Shell lesen. Später ersetzt archguard update die installierte Binärdatei nach denselben Prüfungen durch den neuesten Release. Die Skripte installieren auch die Desktop-App aus demselben Release, geprüft gegen SHA256SUMS-desktop: ArchGuard.app in ~/Applications unter macOS, archguard-desktop (AppImage, x86_64 und aarch64) unter Linux und archguard-desktop.exe unter Windows. ARCHGUARD_DESKTOP=0 überspringt die Desktop-Installation. Führe danach archguard --version und archguard doctor aus.

Aus einem Checkout installieren

Installiere die CLI mit einer aktuellen Rust-Toolchain aus einem ArchGuard-Checkout. Die Desktop-App wird aus demselben Checkout gebaut (siehe unten).

cargo install --path crates/archguard-cli --locked
archguard --version
archguard doctor

Stelle sicher, dass dein Cargo-Binärverzeichnis im PATH steht. Wenn der Befehl nach der Installation nicht gefunden wird, öffne ein neues Terminal oder rufe die installierte Datei direkt auf. Unter Windows heißt sie archguard.exe.

Native Pakete

Wenn im gewählten Repository ein Release verfügbar ist, wähle das Archiv für dein Betriebssystem und deinen Prozessor. Der Release-Workflow baut Windows x64, macOS Apple Silicon und Intel sowie Linux x64 und ARM64. Solange das öffentliche Repository nicht konfiguriert ist, setzt diese Website keine Download-URL voraus.

Prüfe das Archiv gegen das beiliegende SHA-256-Manifest, entpacke es und führe archguard --version aus. Release-Pakete enthalten Prüfberichte und Scan-Logs. Prüfsummen bestätigen die Übereinstimmung mit dem Manifest; sie sind keine Signaturen des Herausgebers. Der aktuelle Paketierungsablauf signiert und notarisiert die Binärdateien nicht.

Dein erstes Projekt öffnen

Starte die ArchGuard-Desktop-App und wähle Datei → Projekt öffnen… (File → Open project… bei englischer Oberfläche). Unter Linux und Windows akzeptiert die installierte App den Ordner auch auf der Kommandozeile. Aus einem Repository-Checkout baust und startest du sie mit Cargo:

archguard-desktop /path/to/project
cargo run --release -p archguard-desktop -- /path/to/project

Nutze für eine Übersicht mehrerer Projekte das Repository-Stammverzeichnis, für eine gezielte Quellsicht das Service-Verzeichnis. Die erste Analyse kann länger dauern, wenn compilerbasierte Belege erhoben werden. Jedes geöffnete Projekt erhält einen eigenen Tab; Datei → Projekt öffnen… fügt weitere hinzu. Die CLI gibt dieselbe Analyse als Text oder JSON aus.

Ohne Konfigurationsdatei leitet ArchGuard Quellverzeichnisse und sinnvolle Standardwerte ab. Auch damit kann es Zyklen melden und eine Prüfung fehlschlagen lassen. Ein Start ohne Konfiguration bedeutet nicht, dass alle Findings deaktiviert sind.

Eine Prüfung ausführen und das Ergebnis lesen

archguard check /path/to/project
archguard cycles /path/to/project --format json
archguard diagram /path/to/project

Exit-Code 1 bedeutet bei einer Prüfung, dass Architektur-Findings das konfigurierte Gate überschritten haben. Das unterscheidet sich von einem Werkzeug- oder Konfigurationsfehler. Lies die Findings und ihren Analyseumfang, bevor du Regeln änderst.

Den Umfang ausdrücklich festlegen

archguard init /path/to/project
archguard config /path/to/project --format json

init schreibt eine erste Konfiguration für ein Projekt ohne vorhandene Konfiguration; es überschreibt keine bestehende Datei. Prüfe den erzeugten Umfang und die vorgeschlagenen Gates, bevor du sie als Teamregeln verwendest. Siehe Konfiguration und Regeln.

Ein Beispiel auswählen

  • Service Shop (EN): enthaltenes Beispiel mit bewusst zyklischen HTTP-Beziehungen; die Analyse benötigt keine Container.
  • Commons Collections (EN): eine versionierte Java-Bibliothek für Paketgraphen und Matrix.
  • Microsoft eShop (EN): ein echtes .NET-Microservice-Beispiel mit einer abgeleiteten Ereigniszyklusgruppe.
  • Apache Kafka (EN): 3.369 produktive Java-Dateien mit Zyklusgruppen auf Dateiebene und einer offline erzeugten Landkarte.
  • OpenTelemetry Demo (EN): ein mehrsprachiges Compose-System mit quellbelegten gRPC-Aufrufen und einem Konfigurationszyklus.

Optionale Datenbankunterstützung

Die Graphdatenbank ist optional. CLI und Desktop-App funktionieren ohne sie. Um Datenbankbefehle und Cypher-Abfragen beim Bauen aus den Quellen zu aktivieren, installiere CMake und eine C++-Toolchain und baue anschließend mit Datenbankunterstützung:

cargo install --path crates/archguard-cli --features db --locked

Die standardmäßigen nativen Release-Archive enthalten diese optionale Funktion nicht.
