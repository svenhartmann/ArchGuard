Troubleshooting

Resolve missing data, unexpected findings and navigation questions.

On this pageThe graph or service view is emptyMetrics are unknown or unavailableUnresolved importsA new cycle appears after an updateViewer controls or links behave unexpectedlyImported evidence is stale or unmappedPort already in useReport a reproducible problem

The graph or service view is empty

Check the analyzed root first. Source graphs, repository inventory and service topology are different scopes. Confirm source roots, language selection, exclusions and the current view's filters. In Services, choose a relationship kind for which evidence exists. A project can be valid without any detected service communication.

archguard config . --format json
archguard scan . --format json
archguard services . --format json

Metrics are unknown or unavailable

Use archguard doctor to inspect tool availability, then archguard calls . --format json for actual compiler diagnostics. Match the project's target framework, JDK and dependency references. Rust, Python and PHP measure classes and functions from syntax, so their analysis is partial. Rust can add call targets from rust-analyzer after opt-in; Python and PHP leave calls and types unresolved. Kotlin provides the import graph only.

Coverage, mutations and runtime measurements need imported reports. Installing a compiler will not create those measurements. Do not substitute zero for missing data.

Unresolved imports

An unresolved import can refer to an external dependency, generated code, an excluded local file or syntax outside a supported resolver's scope. Inspect its source location and compare it with the configured source roots. Language-specific compilers can provide richer evidence where an adapter exists, but dynamic resolution is still bounded.

Do not remove warnings simply because the graph looks plausible. Keep external references distinct from internal relationships and fix scope mistakes before changing architecture rules.

A new cycle appears after an update

Compare the source revision, parser version, selected evidence types, scope and aggregation level. Improved resolution can expose relationships that were previously absent. A file-level cycle can differ from a package-level group. Inspect the exact edges and source evidence before rewriting code or accepting a new baseline.

Viewer controls or links behave unexpectedly

  • Select a package before using Incoming or Outgoing.
  • Use Details or Enter to open an overlay; selection alone need not open it.
  • Use Back or the breadcrumb after drilling into World View.
  • Large graphs benefit from narrower scope, search and limited expansion.
  • Deep links assume the same checkout and a server on the recipient's own machine.
  • After replacing the CLI, restart an existing serve or MCP process. Reloading the browser does not replace the running server executable.

Imported evidence is stale or unmapped

Check the report's source revision and path roots. Reports generated in a container may contain paths that differ from the local checkout. Supply the appropriate source root when importing and inspect unmapped entries instead of treating them as uncovered or clean files.

Port already in use

archguard serve . --port 8788

Choose a different loopback port, or use --port 0 and open the address printed by the process. Do not stop an unrelated server just to reuse its port.

Report a reproducible problem

Include the ArchGuard version, operating system, exact command, effective configuration, source revision, expected behavior and a small reproducible input when possible. For metric problems, include compiler/tool versions and diagnostics. Remove credentials and unrelated private source before sharing logs or reports.
