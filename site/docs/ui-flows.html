ARCHGUARD HANDBOOK

Screens and navigation

Understand routes, user actions and the backend calls behind an application.

Trace a screen into the backend

  1. Open your project and select Screens, then the frontend application.
  2. Select a screen. Read its route, declared access, outgoing navigation and HTTP actions.
  3. Follow an action to its matching endpoint and handler. Use source locations to inspect code, or follow the handler into Calls.
  4. Where recognized, continue into use cases, state transitions and events in the domain model.

Inspect the same model in the CLI

archguard ui-flow .
archguard ui-flow . --format json
archguard ui-flow roles .
archguard ui-flow . --anonymous
archguard ui-flow . --role Admin -v

Replace Admin with a role from your project. Repeat --role to combine roles; do not combine it with --anonymous. Verbose text output shows more than the first ten gap diagnostics.

Read gaps and reachability correctly

A surely reached screen has a known path with supporting conditions. Possibly reached means a condition remains unknown. No known path can mean unresolved navigation; it does not establish that access is forbidden. Without a root route or recognized entry, the model reports no start screen.

Access not declared is a separate state. A missing guard is not an explicit grant. See roles and permissions for the distinction between declared access, evaluation and whole-path reachability.

Open a running local application

Static analysis does not start your application. Once it is running, configure its real application name and URL in .archguard/archguard.toml:

[views.run.WebApp]
base_url = "https://localhost:7298"
login_path = "/user/login"

[views.run.WebApp.users.Admin]
login = "admin@example.org"
password_env = "ARCHGUARD_PW_ADMIN"
archguard ui-flow open "/orders/:id" . --param id=4711 --print

Replace the route and parameter with actual model values. --print displays the resolved URL without opening a browser. Ambiguous matches list candidates. Literal passwords in configuration are rejected; credentials can use an environment variable or the supported macOS keychain setting.

Generate a Playwright replay

archguard ui-flow replay "/orders" . --anonymous --out ./replay.spec.ts

The command writes a test for the shortest resolved path. Review it and place it where @playwright/test is available. Execution requires the explicit --run flag and a running target application. Known triggers are used where available; direct navigation is marked as weaker evidence. This is a browser workflow, not a general native-desktop replay driver.

When a route is missing

Check the selected application, source scope and diagnostics. Adapters read known static patterns; computed routes, dynamic registries and custom clients may remain gaps. Supported UI adapters include Blazor, Angular, React, Vue, Svelte, XAML, Slint and supported Rust UI patterns, with different coverage. You can merge neutral ui-flow/v1 input from .archguard/ui-flow.json; invalid input is an error.

For a separate backend repository or custom guards, use the access configuration.
