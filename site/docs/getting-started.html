Getting started

Install from a checkout

From an ArchGuard repository checkout, use a current Rust toolchain to install the CLI. The browser viewer is embedded in the executable; it does not need a separate frontend build.

cargo install --path crates/archguard-cli --locked
archguard --version
archguard doctor

Make sure your Cargo binary directory is on PATH. If the command is not found after installation, reopen your terminal or invoke the installed executable directly. On Windows the executable is archguard.exe.

Native packages

When a release is available in your chosen repository, select the archive for your operating system and processor. The release workflow builds Windows x64, macOS Apple Silicon and Intel, and Linux x64 and ARM64. No download URL is assumed on this site until the public repository is configured.

Verify the archive against its accompanying SHA-256 manifest, extract it, and run archguard --version. Release bundles include verification reports and scan logs. Checksums establish consistency with the manifest; they are not publisher signatures. The current packaging workflow does not sign or notarize the binaries.

Open your first project

archguard serve /path/to/project --port 8787

Open http://127.0.0.1:8787/. Use the repository root for a multi-project overview, or a service directory for a focused source view. Initial analysis can take longer when compiler-backed evidence is collected. The viewer refreshes as supported source and configuration inputs change.

With no configuration file, ArchGuard derives source roots and sensible defaults. It can still report cycles and fail a check under those defaults. Starting without configuration does not mean all findings are disabled.

Run a check and inspect the result

archguard check /path/to/project
archguard cycles /path/to/project --format json
archguard graph /path/to/project --format html

A check exit code of 1 means architecture findings crossed the configured gate. It is different from a tool or configuration failure. Read the findings and their analysis scope before changing rules.

Make the scope explicit

archguard init /path/to/project
archguard config /path/to/project --format json

init writes an initial configuration for a project that has none; it refuses to overwrite an existing configuration. Review the generated scope and suggested gates before treating them as team policy. See Configuration & rules.

Choose an example

  • Service Shop: included, deliberately cyclic HTTP relationships; no containers needed for analysis.
  • Commons Collections: a pinned Java library for package graphs and the matrix.
  • Microsoft eShop: a real .NET microservice example with an inferred event-cycle group.

Optional database support

The graph database is optional. The CLI and viewer work without it. To enable database commands and Cypher queries when building from source, install CMake and a C++ toolchain, then build with database support:

cargo install --path crates/archguard-cli --features db --locked

The default native release archives do not include this optional feature.
