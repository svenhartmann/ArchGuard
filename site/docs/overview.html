What is ArchGuard?

ArchGuard is developed as a non-commercial open-source project. It is available under MIT OR Apache-2.0; both licenses also permit commercial use of the software.

ArchGuard is a local software architecture analysis tool: a command-line application, an interactive browser viewer and an MCP server for coding agents. It turns supported source code and project configuration into dependency graphs, finds strongly connected groups, evaluates declared boundaries and connects findings to source evidence.

Its main workflow is explore → inspect evidence → declare intent → check changes. Start with a repository overview, drill into services and packages, follow incoming and outgoing dependencies, then make selected architecture constraints repeatable in CI. The same project evidence can be queried by an agent through MCP.

What it is — and what it is not

ArchGuard providesThe boundary
Source and configuration analysisSupported parsers and compiler context determine coverage. Reflection, generated code and dynamic resolution can leave gaps. Import analysis and resolved call analysis have different precision.
Architecture checksCycles, dependency constraints and configured gates describe structural properties. A cycle alone does not establish a defect or infinite execution.
Service relationship evidenceConfigured routes, inferred source candidates and imported runtime observations are distinct. Static analysis does not prove production traffic.
Metrics and imported measurementsCoverage, test outcomes, mutations and runtime measurements need their own producers. Unknown values remain unknown. A health score is a summary, not a quality certification.
Architecture documentationGenerated arc42 evidence and package diagrams support documentation. They cannot infer all business goals, quality requirements or architecture decisions.
Agent access and refactoring simulationMCP exposes analysis workflows; simulation changes a hypothetical graph. Neither guarantees a safe source-code change. Validate edits with fresh analysis and project tests.

ArchGuard is not an APM agent, a production monitoring backend, a test runner, a complete security scanner or a general-purpose C4 authoring suite. It can consume evidence from other tools; it does not replace their measurements or operational workflows. Dependency vulnerability scanning delegates to Trivy, and compiler-backed source analysis requires compatible language tools.

One question, several evidence layers

“Can we change Ordering safely?” In Microsoft eShop, ArchGuard can show Ordering's package dependencies, infer event routes from publishers, subscriptions and shared RabbitMQ configuration, and highlight a structural cycle group. You can inspect the exact references and zoom into the service. Without imported traces, it cannot tell you which routes carried production traffic, their latency or how often a handler failed. Without test evidence, it cannot claim the change is sufficiently tested.

A practical adoption path

  1. Open one representative repository and inspect coverage and missing evidence.
  2. Review a dependency cycle and a service relationship against their source references.
  3. Declare a small number of agreed boundaries and introduce a reviewed baseline where needed.
  4. Keep your existing tests, security analysis, monitoring and architecture decision records. Import supported evidence where it adds context.
  5. Evaluate precision, analysis time and usability on your own codebase before expanding CI enforcement.
