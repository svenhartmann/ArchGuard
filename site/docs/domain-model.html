ARCHGUARD HANDBOOK

Domain models

Read entities, rules, state changes and event chains with their source evidence.

Explore modules, then entities

  1. Open Domain and select a service or the whole model.
  2. For larger models, start with the module overview. Open a module to inspect its entities and cross-module references.
  3. Select an entity to read fields, relationships and rules. Recognized API models are listed separately from domain entities; classification follows the supported patterns.
  4. Select a state to trace its possible causes, or an event to inspect publishers and handlers across service lanes.

Query entities and state changes

archguard domain .
archguard domain . --format json
archguard domain . --entity Order
archguard domain . --chain
archguard domain . --entity Order --state Paid --role Admin

Order, Paid and Admin are project-specific examples. A state query requires an entity. Role simulation requires a chain or state query; use --anonymous instead of roles for anonymous access.

Distinguish a transition from a rule

A transition guard describes when the change is allowed. A rule condition describes when the method throws. The perspectives can be opposite; a recognized return/throw guard can appear as !(original condition). These expressions remain source text, not solved business predicates.

Recognized FluentValidation rules and Bean Validation annotations appear as validation evidence. Relationships distinguish one, many and references. Reported gaps identify unreadable relationships or states. An absent row does not prove the corresponding feature is absent.

Follow causes and effects

Chains connect endpoint → use case → transition → event → handler. Reverse state lookup asks what can cause the selected state. Integration events can continue across services; nested chains are bounded and do not revisit the same handler.

These are static relationships, not a recorded execution. Message-handler starts are not user paths, so they are not authorization failures. Background jobs are not recognized chain starts. Use runtime evidence to inspect actual observations.

Understand extractor coverage

Domain extraction covers recognized C#, Java/Kotlin, TypeScript and Python patterns. TypeScript includes TypeORM/MikroORM markers, Prisma, supported table decorators and NestJS CQRS patterns; Drizzle builders and Kysely row maps are not domain entities. Python supports Django, SQLModel and SQLAlchemy patterns, but not Python event/use-case chains.

Neutral domain-model/v1 input in .archguard/domain-model.json supplements extraction. Invalid imports are errors. Do not assume arbitrary domain naming conventions or custom state libraries are inferred.

Ask the model through MCP

Call domain_model with {"entity":"Order"}, {"chain":true} or {"entity":"Order","state":"Paid","roles":["Admin"]}. Follow the returned pagination and revision; preserve unknown access and coverage in the explanation.
