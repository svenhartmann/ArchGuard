What works without extra tools

The ArchGuard executable reads source and configuration files directly. Import graphs for all supported languages, cycles, the matrix, World View, rules and static service discovery need nothing else. ArchGuard never downloads, builds or restores your project. When a tool or a project prerequisite is missing, the affected analysis is reported as unavailable or partial rather than failing the run.

Languages

Classes, methods, calls and class metrics (CBO, RFC, WMC, LCOM4 …) come from each language's own compiler. That compiler must be installed and must be able to resolve your project's dependencies.

LanguageWithout extra toolsTool to installYour project must provide
JavaImport graphA full JDK 17+ (a JRE is not enough), available as java on PATH. JAVA_HOME is not consulted.The dependency classpath, either in .archguard/java-classpath.txt (one line, exported from Maven or Gradle) or as semantic.java.classpath in the configuration. ArchGuard runs no build. The release level is read from pom.xml / build.gradle(.kts), or set with semantic.java.release.
C#Namespaces and imports.NET SDK 8+, available as dotnet on PATH, including the reference pack for your target framework (Microsoft.NETCore.App.Ref).Run dotnet restore first so that obj/project.assets.json exists. Project references and local HintPath assemblies are read. SDK-style projects using Microsoft.NET.Sdk or Microsoft.NET.Sdk.Web are supported.
TypeScript / JavaScriptImport graphNode.js as node on PATH. The TypeScript compiler is not bundled; ArchGuard uses your project's copy and runs it only when ARCHGUARD_TRUST_PROJECT_COMPILER=1 is set.TypeScript installed in node_modules (npm install), or its path in semantic.typescript.compiler. A tsconfig.json or semantic.typescript.project. JavaScript files are analysed only with allowJs.
GoImport graphThe Go SDK, as go on PATH or with ARCHGUARD_GO pointing to the executable. The helper is built offline with the local toolchain.Nothing. Third-party modules are not resolved, so calls into external modules stay partial; repository sources and the standard library are analysed.
RustDeclarations and per-function complexity, cognitive complexity and Halstead metrics from syntax; call targets after opt-inNone for metrics. For call targets: rust-analyzer and ARCHGUARD_TRUST_PROJECT_COMPILER=1.Nothing. Types stay unresolved; without the opt-in, calls do too.
PythonClasses, functions and per-function complexity, cognitive complexity and Halstead metrics from syntaxPython 3.9+ on PATH, or ARCHGUARD_PYTHON pointing to it. The bundled helper runs isolated and never imports project code; imports need no Python.Nothing. Calls and types stay unresolved. Files using newer syntax than the local Python are reported, not measured.
PHPClasses, functions and per-function complexity, cognitive complexity and Halstead metrics from ArchGuard's token scannerNone (no PHP installation)Nothing. Calls and types stay unresolved.
KotlinImport graph, resolved together with JavaNoneNothing. No class metrics; Gradle .kts scripts are not scanned.
Protocol BuffersServices and messages from .proto filesNone (no protoc)Nothing.
# Java: export the classpath once, e.g. with Maven
mvn -q dependency:build-classpath -Dmdep.outputFile=.archguard/java-classpath.txt

# C#: restore packages so obj/project.assets.json exists
dotnet restore

# TypeScript: install the project compiler, then allow ArchGuard to run it
npm install
ARCHGUARD_TRUST_PROJECT_COMPILER=1 archguard serve . --port 8787

The Maven command is one way to produce the classpath line; with Gradle, write the resolved runtime classpath to the same file. Use archguard calls . --format json to see per-language status and the gaps that remain.

Git history & security scan

FeatureTool to installNotes
Hotspots, co-change, snapshots, diff, quality gates against a baseGit on PATHThe project must be a Git repository with history. A shallow clone with a single commit has no change history to show.
archguard securityTrivy on PATH as trivyRuns trivy fs for dependency advisories. Trivy downloads its database unless you pass --offline (which needs an existing database); --cache-dir chooses its location and --cached reads the last saved result without running Trivy. Lockfiles give transitive coverage, manifests only direct dependencies.

Imported reports

ArchGuard parses these reports; it never runs the producing tool. Generate them with your usual test or analysis setup, then import them.

EvidenceAccepted formatCommand
Test coverageJaCoCo XML, Cobertura XML, Clover XML, LCOVarchguard coverage
Static analysis findingsSARIF 2.1.0 (up to 32 MiB)archguard quality
Test resultsJUnit XMLarchguard test-evidence
Mutation testingmutation-testing-elements JSON (for example from Stryker)archguard mutations
Duplicated codePMD CPD XMLarchguard duplicates

Each command's --help lists its options. See Languages & measurements for how imported measurements are interpreted.

Check your setup

archguard doctor
archguard calls /path/to/project --format json

archguard doctor reports whether git, java, dotnet and node are found and prints their versions. It does not check minimum versions, Go or Trivy, and always exits with status zero. The calls report shows what each language analysis actually achieved for your project, including partial results and their reasons.
