ARCHGUARD HANDBOOK

Runtime and contracts

Bring recorded requests into architecture analysis and keep observations separate from declarations.

Provide an actual recording

  1. Use existing OpenTelemetry instrumentation and a collector/exporter that produces OTLP JSON Lines.
  2. Store recordings under .archguard/runtime/<run>/traces-0001.jsonl.
  3. Analyze the project and open Runtime in the desktop.
archguard runtime . --format json

Each line is one OTLP request containing resourceSpans. The legacy .archguard/otel-traces.json accepts one JSON document. The command reads recordings; it does not start your application, launch a collector or generate traffic. Without recordings, the runtime view has no measurements.

Follow a request

Start with the time overview and endpoint breakdown, then choose a request and inspect its span timeline or flame graph. Live mode reads newly written recordings. Examine repeated queries, database calls per request and mapped code locations.

Useful attributes include service.name, http.route, code.file.path, code.line.number and code.function.name. Ordinary OpenTelemetry input works; optional ArchGuard attributes enrich it. Missing mappings stay unmapped. Probe builds described in the repository are not assumed to be public package releases.

Interpret database indicators

These supported defaults can be configured in .archguard/archguard.toml:

[runtime]
n_plus_one_min_calls = 5
chatty_endpoint_db_calls = 20.0
slow_statement_ms = 100.0

N+1 candidates group the same statement at the same call site within one request. Without call-site information, grouping falls back to the statement. Chatty endpoints use database calls per request at p95. Slow statements use client-observed execution duration at p95, which can include network or pool waits. A threshold crossing needs investigation, not an automatic defect label.

Compare declarations and observations

archguard services . --format json
archguard contracts . --report openapi.yaml --service ACTUAL_SERVICE_ID
archguard contracts .
archguard runtime .

Generate or obtain the OpenAPI file first. Replace ACTUAL_SERVICE_ID with an ID from the topology. The import saves explicit contract evidence; a plain contracts query reads saved evidence and discovered GraphQL schemas.

Contracts describe declared interfaces; traces describe captured executions. Use them alongside source and configuration relationships. Missing traces do not prove an interface unused. Contract payload shapes can inform a load scenario, but do not automatically supply measured transfer sizes.

Check recording coverage

The reader scans up to four directory levels, refuses symlinks and reports incomplete coverage at input limits: 16 MiB per line, 1 GiB per file and 500,000 spans in total. Trace/span IDs are deduplicated. The legacy JSON document has a 16 MiB limit.

Sampling, missing spans and unrecorded traffic limit conclusions. Optional profiler samples retain their clock and interval; missing samples are unknown, not zero CPU time. For agents, use runtime_profile and preserve coverage in the answer.
