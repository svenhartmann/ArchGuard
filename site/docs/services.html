Project inventory is not service inventory

A repository can contain applications, libraries, tooling and workspace aggregators. A manifest establishes a project boundary; it does not automatically establish a deployed service. For example, a Rust binary can be an application project without being classified as a service.

archguard services . --format json
archguard workspace . --format json
archguard workspace . --sources --format json

services discovers supported deployment and communication evidence. workspace starts with declared dependencies between projects; source analysis is opt-in with --sources. Neither command should be read as a complete runtime map.

Connection types

RelationshipWhat it establishesWhat it does not establish
Configured HTTPA literal supported HTTP destination or route in configuration.That a request actually occurred.
StartupA declared startup dependency such as Compose depends_on.An application API call.
HTTP / gRPC clientA supported static client-call candidate and its source evidence.All dynamically constructed endpoints or actual traffic.
Event flow (inferred)Matching supported publish/subscribe evidence, event identity and shared broker context.Delivery, ordering or a production message trace.
Configuration referenceA declared relation between configured resources.Communication merely because resources are mentioned together.
Observed tracesConnections supported by imported usable trace evidence.Complete traffic coverage outside the captured window.

Interpret a cycle precisely

A cycle group is calculated for the selected relationship kind. A startup cycle and an event-flow cycle are different findings. Selecting Cycles only narrows the visible relationships; it does not convert configuration evidence into runtime proof.

An event-driven business workflow can legitimately form a structural cycle. Inspect contracts, responsibility boundaries and actual message handling before proposing a change. The graph alone cannot establish a retry storm or infinite message loop.

A real example: Microsoft eShop

At the documented revision, Catalog API, Ordering API and Payment Processor form a three-service event-cycle group. Ordering requests stock validation, Catalog returns stock outcomes, Ordering triggers payment processing, and Payment Processor returns payment outcomes. Source details identify the publish and subscription sites.

Use the main Aspire deployment scope to keep test-host variants separate. Follow the eShop walkthrough and the service screenshots.

Move from service to code

Select a service in World View and choose Zoom into service, or use the area selector. The source view opens that project's own scope. Infrastructure without local sources cannot provide a class drilldown. Return through the repository breadcrumb to inspect cross-service relations again.

When a connection is missing

  1. Confirm the intended deployment variant, relation kind, evidence source and direction filter.
  2. Inspect discovery exclusions, ignored files and the selected repository root.
  3. Read diagnostics for unsupported configuration, missing source references or dynamic endpoints.
  4. Distinguish a library reference from an actual service call.
  5. If runtime evidence is required, import suitable traces rather than treating static candidates as observed calls.

Nested examples, fixtures, agent worktrees and generated output are excluded from normal repository discovery. Open an example directory explicitly when you intend to analyze it.
