Feature coverage

UI flows, domain models and load scenarios take ArchGuard beyond dependencies. Find the capabilities and their practical guides here.

UI flows, the permission matrix and domain models are implemented in the integrated source snapshot. The guides below explain how to use them. Load simulation uses a separate build, detailed below.

UI flows and navigation

Which screens exist, where does an action lead, and which backend call follows? Screens, transitions and actions retain source locations; dynamic targets remain explicit gaps.

Guide and examples

Roles, permissions and policies

Read role hierarchies, permission IDs and declared policies from code. Simulate a role or anonymous access as allowed, denied or unknown. Undeclared backend access stays unknown.

Guide and examples

Permission matrix

Screens and endpoints as rows, roles as columns; table, JSON or CSV output and MCP access. Screen cells evaluate their own access condition, not the entire navigation path.

Guide and examples

Compare frontend and backend access

Inspect visible actions refused by the backend and hidden actions lacking backend protection. Conditions, reachability and unknown rules remain part of each finding.

Guide and examples

Open screens and replay paths

Open local screen URLs with route parameters and generate Playwright tests for the shortest resolved click path. Execution is explicit; direct navigation without a known trigger is marked as weaker evidence. Replay is available through the CLI for browser targets.

Guide and examples

Separate frontend and backend repositories

Join frontend actions to endpoints in explicitly configured backend repositories. Missing endpoints and backend gaps remain visible; MCP confines access to its server root.

Guide and examples

Domain model from code

Read aggregates, entities, value objects, fields and relations through defined patterns. List API models and DTOs separately instead of counting them as domain entities. Imports cover patterns without extractors.

Guide and examples

States and transitions

Derive state machines from enum fields and readable assignments. Transitions show their method, guard and raised events. Computed states are not guessed; guards are source text, not a general proof of business logic.

Guide and examples

Business rules and validation

Show conditions under which entity methods throw, with message and source location. Include FluentValidation rules and Bean Validation annotations; the desktop Domain view presents them alongside states.

Guide and examples

From a click to a domain event

Follow action → endpoint → use case → state change → event → handler. Reverse lookup asks which screens, endpoints or messages can cause a state such as Paid. Role evaluation preserves unknown results.

Guide and examples

Event chains across services

Follow integration events into message handlers and further use cases. Nested chains are bounded and do not revisit a handler; they describe static relationships, not measured runtime sequences.

Guide and examples

Python domain models

Read entities and relationships from Django, SQLModel and SQLAlchemy, including supported base classes. Django TextChoices with literal transitions and certain ValidationError/ValueError rules enrich the view. Unresolved relationships remain gaps.

Guide and examples

Conventions as CI checks

Opt into checks for readable navigation and HTTP URLs, declared endpoint access, frontend/backend agreement, state changes and event creation. New checks find targets without matching routes and endpoints without detected UI calls; external clients can explain the latter.

Guide and examples

Review notes for coding agents

Record fix, intentional acceptance or defer decisions with reasons on gaps and findings. CLI, MCP and SARIF carry them forward; baselines and valid acceptance decisions affect the gate explicitly.

Guide and examples

What-if load and capacity

Vary explicit entry points, call rates, instances and service times. Unknown inputs produce ranges; potential bottlenecks name their assumptions and drivers. CLI, MCP and World View expose the same scenario model.

Guide and examples

Queues, pools, locks and waits

Show concurrency candidates with source location, readable capacity and confidence in load reports. They guide investigation and do not automatically become numerical capacity inputs.

Guide and examples

Payload shapes along connections

OpenAPI, AsyncAPI and Protobuf contracts provide fields, types and nesting. JSON sizes remain ranges with an open upper bound when the schema supplies no bound. Shapes do not automatically change assumed transfer sizes.

Guide and examples

Reproducible discrete-event simulation

A seed makes discrete-event simulation repeatable as an alternative to M/M/c queue formulas. Both bounds of unknown inputs are retained. Timeouts, retries and bursts are not yet modeled in this model.
