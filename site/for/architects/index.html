Check actual dependencies against the target architecture and keep arc42 aligned with the implementation. ArchGuard connects source analysis, declared boundaries and documented review decisions.

Desktop, CLI and MCP

Keep arc42 close to the code

Refresh evidence in twelve arc42 chapters while preserving protected manual text. Export to Markdown, AsciiDoc or Word; keep the reasons behind decisions in your own words.

Make the target explicit

Declare logical components and allowed dependency directions. Compare that model with actual imports, and connect quality goals to the evidence that can assess them.

Make reviews reproducible

Compare Git revisions, inspect KPI deltas and keep review decisions with their rationale. An accepted risk can require an ADR through the project policy.

Go deeper

Derive system boundaries for architecture reviews

Define the system boundary using the applications, interfaces and datastores identified in the project. The derived arc42 context supplies the technical foundation; your team adds business goals and architecture decisions.

Analysis scope and prerequisites

A diagram describes the available source and configuration. It cannot supply a missing architectural decision. A quality goal with no findings is not proof that the goal is met. Word exports retain diagrams as source text; rendering and Confluence import are separate steps.
