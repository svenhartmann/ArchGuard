Desktop, CLI and MCP

Start with bounded context

Use change_context for exact files, unique symbols or a Git base. Follow pagination with its revision so a small response is never mistaken for the complete graph.

Explain before changing

Ask for cycle groups, source locations and coverage gaps. Keep imports, configured service connections and observed traces separate in the answer.

Try a virtual refactoring

Simulate a cut, move or merge and inspect the graph delta before editing source. Compare the actual change afterwards to see whether it produced the intended structural result.

Focused change context through MCP

With change_context, an agent retrieves dependency context for specific files, symbols or a Git comparison. Source locations and analysis limits make the response verifiable; pagination bounds the size of each query.

Get started

Connect the local analysis to your client

After installing ArchGuard, this starts a stdio server for the included Service Shop example from the ArchGuard repository root. Configure your MCP client to launch it; use the absolute project path in client settings. It waits for protocol messages, not an interactive shell prompt.

Set up your MCP client
archguard mcp --root "$PWD/examples/service-shop"

A first question to ask

Show the service cycle groups in this project. For one connection, give the source location, the evidence kind and anything the analysis cannot establish. Do not change files.

Analysis scope and prerequisites

Static relationships do not prove runtime behaviour. Simulations describe a hypothetical graph, not a working refactoring. Some MCP operations write project artifacts; distinguish explanation from action. The server runs locally, but your agent client may send its responses to its configured model provider.
