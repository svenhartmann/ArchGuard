For teaching and learning

Make architecture observable.

A box-and-arrow diagram becomes more useful when students can inspect the code behind an arrow. Use reproducible examples to test an architectural claim together.

A cycle is visible. What does it actually prove?

Ask students to distinguish a structural dependency from an executed request, then justify a proposed change.

Missing evidence is not a zero. See what was measured, what was inferred and what remains unknown.

Three ways to start

Start with an inspectable example

Use the included Service Shop demo or pinned open-source walkthroughs such as Commons Collections, eShop, Kafka and the OpenTelemetry Demo. Keep the revision and analysis scope with every result.

Move between representations

Compare the World View, package graph and dependency matrix. Follow a selected connection back to its source; discuss why aggregation can reveal different cycle groups.

Evaluate a proposed change

Describe a cut, move or merge and inspect the virtual graph result. Then discuss the source edits, tests and business tradeoffs that the graph cannot decide for you.

Go deeper

A small service cycle with a business reason

Service Shop is an intentionally coupled demo. Catalog requests prices, Pricing asks Promotions for discounts, and Promotions reads categories from Catalog. The return request uses a different endpoint: a structural cycle is not proof of infinite recursion.

Get started

Turn the observation into a gate

After installing ArchGuard, run this from the ArchGuard repository root. The included demo needs no running containers. Expect exit code 1 because configured HTTP cycles are present; this is the lesson’s finding, not an installation failure.

Check language prerequisites
archguard services examples/service-shop --fail-on-found

A short classroom exercise

  1. Observe. Find Catalog → Pricing → Promotions → Catalog. Record the evidence kind and the source location for each edge.
  2. Explain. Explain why the cycle does not establish infinite recursion. Compare HTTP configuration with startup dependencies.
  3. Argue. Propose passing the category with the price request. Explain which dependency could disappear and which behaviour tests would be needed.

Know the evidence boundary

Service Shop is a teaching demo with in-memory data and mock payments, not a production system. Pinned third-party examples retain their own licenses. Missing compiler tools or runtime traces limit what can be concluded; a grey or unknown measurement is never a zero.
