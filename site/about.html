EXAMPLES & EVIDENCE

About these examples

Real desktop app captures, with their scope kept visible.

The original capture set, including the unchanged flow video, was rendered headless with ArchGuard desktop 0.3.3 on 10 November 2026 at 1480 × 920 points (2× scale). Its example source revisions were Apache Commons Collections 4.6.0 at revision 4107624de41aeed37985d2a069fad41992fd71a2, Microsoft eShop at revision 913acea66708a59595351174cee9b29f37179d29, the included Service Shop, the OpenTelemetry Demo at revision 33bd823107b1b38eaa88dd4ef625cc16d60475d4 and Apache Kafka at revision 13f70256db3c994c590e5d262a7cc50b9e973204. The video turns the World View through 72 captures 5° apart and then joins six further views with short fades; it contains no simulated clicks. No graph or measurement was painted into the images. The PNG refresh is documented separately below.

New language-gallery captures have their own revision, tool and scope records in the language gallery. Screenshot reuse on a feature section illustrates the named view; a caption does not turn a static map into a CI result or runtime trace.

What the screenshots show

  • World View, Graph, Matrix, Calls and Quality: Apache Commons Collections with the repository's example configuration and production-source scope. The World View metric images use the Explore lens with Complexity, CBO, WMC and LCOM4; the package image opens org/apache/commons/collections4/map. Class metrics are partial where compiler-backed analysis did not cover a class.
  • arc42 documentation and context diagram: Architecture tab, chapter 5 (building block view) of Apache Commons Collections and chapter 3 (context and scope) of Microsoft eShop. The diagrams are derived from source and configuration; they do not establish a complete system context.
  • Service map and source evidence: Microsoft eShop with the aspire:src/eShop.AppHost/AppHost.cs deployment, inferred event flow and Cycles on the Start tab; on the Services tab with catalog-api selected. The Catalog / Ordering / Payment Processor cycle is inferred from source and shared RabbitMQ configuration; it is not an observed runtime trace.
  • OpenTelemetry Demo: Services tab with gRPC client relations and checkout selected, and with configuration references and otel-collector selected, its cyclic group in red. Both are static candidates from source and compose.yaml, not observed traffic.
  • Apache Kafka: Start tab, Architecture, Problems lens inside org/apache/kafka, with the repository's example configuration. Java analysis is partial.
  • Services on the Service Shop page: Service Shop with API configuration and pricing selected. The two highlighted groups are configured HTTP cycles.

Screenshots show analysis at a point in time. Counts depend on the source revision, filters, graph granularity and available analysis tools. They are not a promise of complete runtime coverage.

Evidence and limitations

ArchGuard separates source dependencies, deployment configuration, declared architecture and imported runtime evidence. Missing references, dynamic dispatch and generated code can leave analysis gaps. Coverage and runtime metrics require imported measurements; unavailable values are not treated as zero.
