Which architecture tool fits?

Compare architecture tools against your workflow: enforce rules in the build, investigate dependencies interactively, maintain documentation or provide context to coding agents.

Where ArchGuard fits

You want to start from source and project configuration, explore the result in a native desktop app, and query the same analysis from a CLI or coding agent through MCP. ArchGuard connects package and file graphs with supported deployment evidence, imported measurements and arc42 documentation.

It is a non-commercial open-source project under MIT OR Apache-2.0. Starting needs no configuration file; rules, intended architecture boundaries and runtime evidence require deliberate inputs. Scope and purpose · MCP guide

Analysis scope and prerequisites

  • An import edge does not prove a runtime call.
  • Compiler-backed method and type information depends on language support, tools and available references.
  • Deployment configuration establishes configured relationships; traces only cover recorded executions.
  • A simulation changes a hypothetical graph. It does not implement a refactoring or establish behavioural equivalence.

Missing evidence is not a zero. An unknown value is not a favourable measurement. Why the distinction matters.
