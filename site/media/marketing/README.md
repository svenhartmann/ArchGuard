# Marketing captures

These are real offscreen renders of ArchGuard's desktop widgets, recorded on
2026-11-20 from fresh public upstream clones. No graph, terminal output or metric
was painted into an image. The projects are pinned in `sources.json`, including
the exact requested source configuration and the hash of each upstream license file.
The desktop repository overview can additionally aggregate discovered project scopes
(for example NestJS samples); the screenshot keeps that broader overview visible.

Build the desktop app at the `archguard_source_commit` in that manifest:

```sh
cargo build --locked -p archguard-desktop -p archguard-cli \
  --features archguard-desktop/snapshot
python3 site/media/marketing/capture.py \
  --app target/debug/archguard-desktop \
  --sources /tmp/archguard-marketing-fresh-sources
python3 site/media/marketing/record-session.py \
  --cli target/debug/archguard \
  --project /tmp/archguard-marketing-fresh-sources/commons-collections \
  --out site/assets/marketing/mcp-session.json
python3 site/media/marketing/record-cli.py \
  --cli target/debug/archguard \
  --sources /tmp/archguard-marketing-fresh-sources
python3 site/media/marketing/render-gallery.py
```

Use a fresh sources directory; the script clones only the pinned revisions. It
refuses different revisions, tracked source modifications and different existing
configuration. `--only kafka-world,kafka-matrix` selects individual captures.
`--timeout` is the per-capture time budget in seconds. Compiler availability can
change measurements, so compare the actual screenshots and keep missing-evidence
indicators visible. The recorded run used macOS and JDK 23; it did not install
project dependencies, enable a project TypeScript compiler, enable rust-analyzer,
or render Helm/Kustomize. A Go SDK was unavailable. The C# and Java compiler
evidence is partial where dependency metadata is missing.

## What the evidence establishes

- `boutique-services.png`: Online Boutique's statically discovered service
  topology. The pinned repository contains Kubernetes manifests, a Helm chart,
  Kustomize overlays and Terraform; this capture does not prove that every
  deployment variant was rendered. The default run leaves rendering disabled.
- `boutique-datastore.png`: the configured `redis-cart` dependency and its manifest
  evidence. The accompanying `boutique-services.json` retains datastore discovery
  and its diagnostics. Neither establishes live traffic or shared-table access.
- `petclinic-ci.png`: a deliberately restrictive **local teaching policy** rejects
  Owner's dependency on model classes. This is an illustrative gate, not a claim
  that Spring PetClinic violates its own architecture. The precise policy is in
  `sources.json`. Sources remain unchanged.
- `petclinic-pr-comment.md`: the real locally generated `review --base` comment,
  compared against the pinned source commit under the same local teaching policy.
  `petclinic-pr-comment.json` records the exact base, target and policy. The recorded raw output
  reports prioritized findings 0 → 1 despite unchanged tracked sources. These
  review candidates are not proof of a source regression; no GitHub post was made.
- `commons-before.png` / `commons-after.png`: a virtual cut from the comparators
  package to `ComparatorUtils.java`. This is an analysis scenario, not a source
  edit or a guarantee that the refactoring preserves behavior.
- `mcp-session.json`: actual JSON-RPC requests and responses, not an invented
  Claude Code dialogue. The originally suggested map → bag example has no edge
  in the pinned production-source scope; the transcript therefore uses the
  verified comparators → ComparatorUtils dependency.
- `eshop-docs.png`: the source/configuration-derived arc42 context view. It is not
  a complete declaration of the system's environment.
- `*-world.png` / `*-matrix.png`: repository overviews with the requested source
  configuration named in the manifest; discovered project scopes may extend
  those filters. These are not cross-language benchmark scores. Grey metric
  surfaces mean unavailable evidence. A matrix is a static dependency graph,
  not observed runtime traffic.

World/feature captures and the Kafka matrix use a 1480 × 920 logical-point window;
other matrix excerpts use a 1480 × 600 window, each at 2× scale. This is a smaller real app viewport, not a
post-processed crop. Fonts and available analyzers can affect pixels on another machine.

The public `assets/marketing/provenance.json` is generated from the same manifest
and actual PNG headers and hashes. EN/DE language gallery pages are generated by
`render-gallery.py`; it fails if a required capture is missing. All source text,
upstream checkouts, local cache files and machine paths stay out of the site.

No shared-table or runtime performance finding is claimed unless an actual
recorded result establishes it. Source declarations and configured endpoints
alone do not prove live database access.

## Local validation

```sh
python3 -m py_compile site/media/marketing/*.py
python3 site/media/marketing/verify.py
```

The repository gates and architecture comparison are also required. The MCP
graph does not represent new HTML, Markdown, PNG or shell capture paths; attempted
`change_context` queries for these return an unknown-target error. This is a
coverage limitation, not a clean architectural finding.
